매출채권 - 회전율, 회수기간, 대손충당금 비율

차입금 - 부채비율, 차입금 증가율, 이자보상배율
ex) 단기차입금 증가-> 유동성 위험 존재

비정상계정 - 기타채권, 선급금, 가수금, 가지급금

이익 조정 가능성 

ex) 매출 급증-> 재고자산 증가-> 현금 감소 -> 매출채권 증가 -> 분식회계 가능성

5. 추가 실무 심화 아이디어 (Claude 추천)
==========================================

[1번 아이디어 심화 - 전수 전표 분석/이상거래 탐지]

- Benford's Law(벤포드 법칙): 전표 금액의 첫째/둘째 자리 숫자 분포가 이론적 분포와
  얼마나 벗어나는지로 조작 가능성 탐지 (실제 포렌식 회계에서 널리 쓰는 기법)
- Beneish M-Score: 8개 재무비율(매출채권지수, 매출총이익률지수, 자산성질지수,
  감가상각지수, 판관비지수, 레버리지지수, 총발생액지수 등)로 분식회계 가능성을
  점수화하는 학술적으로 검증된 모델 -> "AI가 분식 여부를 판단했다"는 근거로
  제시하기 훨씬 설득력 있음
- 전표 테스트 세부 룰 추가 후보:
  * 반올림 숫자 거래(1,000,000원 등 딱 떨어지는 금액) 빈도
  * 회계연도 마감 직전/직후 대량 전표(cut-off 이슈)
  * 수동분개(manual journal entry) 비율 및 작성자-승인자 동일 건
  * 중요성 금액 바로 아래 구간에 몰린 거래(승인 회피 패턴)
- MUS(화폐단위표본추출) 샘플사이즈 계산기: 신뢰수준/허용왜곡/예상오류율/모집단
  입력 -> 자동으로 표본크기 및 표본항목(계통추출) 산출 -> 브레인스토밍한
  "재고실사 적정 샘플링 개수" 질문에 대한 실제 답이 됨

[4번 아이디어 심화 - 재무제표 자동 분석]

- DART Open API 연동: 금융감독원에서 상장기업 재무제표를 무료로 오픈API 제공
  -> 실제 기업 데이터로 데모/테스트 가능 (별도 데이터 확보 불필요, 신뢰도 up)
- Altman Z-Score(부실예측), Piotroski F-Score(재무건전성)까지 함께 제공하면
  "감사인 관점"을 더 학술적으로 뒷받침 가능
- 동일 업종 코드(KSIC) 기업들의 평균과 비교하는 산업평균 대비 분석
- 분석 결과를 실제 감사조서 양식(Word/PDF)으로 export하는 기능
  -> "실무에서 바로 쓸 수 있다"는 인상을 심사위원에게 강하게 줄 수 있음

[2번, 3번 아이디어 관련 참고]

- 2번(AI 계약서 검토)은 LLM API 연동이 필요해 난이도가 높고 리스 판단 기준
  (K-IFRS 1116: 사용통제권/특정자산식별/경제적효익 등) 체크리스트 설계도 필요함
  -> 7일 내 완성도 있게 넣기엔 리스크가 큼. 시간 남으면 2단계 확장 기능으로 고려
- 3번(엑셀 자동화)은 좋은 아이디어지만 1번/4번과 기술 스택(데이터 업로드->
  Python 분석)이 겹치므로, 별도 기능이 아니라 4번의 "결과 export" 파트로
  흡수하는 게 효율적

6. 7일 완성 기준 추천 MVP 범위
==========================================

4개를 다 만들기보다, 1번+4번을 하나의 플로우로 통합하는 것을 추천:

  [전표/재무제표 업로드 또는 DART 연동]
        -> [재무비율 자동 계산 + Benford's Law + Beneish M-Score 이상탐지]
        -> [MUS 샘플링 계산기]
        -> [대시보드 시각화 + 감사조서 형태 리포트 export]

이유: 하나의 데이터 파이프라인으로 "재무제표 분석"과 "이상거래 탐지"를 모두
커버할 수 있고, 회계법인 실무(재무제표 분석 + 부정탐지 + 표본감사)를 압축해서
보여줄 수 있음. 코딩 초심자 기준으로도 기능 확장이 명확한 단계별 구조라 관리가 쉬움.

추천 기술 스택 (비전공자 기준 7일 내 완성 가능성 우선):
- Python + Streamlit: 프론트/백엔드를 분리하지 않고 데이터 앱을 빠르게 구현,
  Streamlit Community Cloud로 무료 배포 가능 (회계 데이터 분석 데모에 최적)
- pandas: 재무제표/전표 데이터 전처리 및 비율 계산
- DART Open API: 실제 상장기업 재무제표 무료 수집
- plotly: 대시보드 시각화
- python-docx 또는 reportlab: 감사조서/보고서 형태 export

- 데이터 입력 2가지 경로 모두 지원:
  (1) DART Open API 연동 -> 상장기업 재무제표 자동 수집
  (2) 엑셀 직접 업로드 -> 비상장법인 내부자료 분석
  * 비상장법인 엑셀은 회사마다 계정과목명/양식이 제각각이라 자유 형식 파싱은

    사용자가 거기에 맞춰 입력/붙여넣기 하는 방식으로 단순화 추천

9. 추가 요청 기능 구체화 (2026-07-20)
==========================================

[A. 이상 변동 계정 자동 탐지]

- 내용: 계정과목별 전기 대비 당기 증감률을 자동 계산하고, 임계치(예: ±20~30%
  또는 업종평균 대비 표준편차 기준) 초과 계정을 자동 하이라이트
- 연관계정 교차검증도 포함: 예) 매출 증가율 대비 매출채권 증가율이 비정상적으로
  높은 계정 조합을 자동으로 짚어줌 (이미 브레인스토밍 4번 항목에 있던 로직의
  구체화 버전)
- 난이도: 낮음 - pandas로 계정과목별 YoY% 계산 + 임계치 비교만 하면 됨,
  새로운 기술스택 불필요
- 배치 위치: Day 3(재무비율 자동계산)에 통합 - 별도 날짜 불필요

[B. 감사 체크리스트 자동 생성]

- 내용: 탐지된 위험 신호(재무비율 이상, Benford/Beneish 이상탐지 결과, 이상
  변동 계정)를 입력으로 받아 "이 위험에 대해 어떤 감사절차를 수행해야 하는지"를
  자동으로 매칭해 체크리스트 형태로 출력
- 구현 방식: 규칙기반 매핑 테이블 (위험지표 조건 -> 추천 감사절차) - AI/LLM
  없이도 구현 가능, 신뢰성도 오히려 높음 (감사기준 근거 명시 가능)
- 매핑 예시:
  * 매출채권회전율 급감 + DSRI 상승 -> "매출채권 조회서 발송 확대,
    회수가능성 재검토, 대손충당금 적정성 검토"
  * Benford 이상 + 반올림전표 다수 -> "해당 구간 표본 확대, 전표 승인
    절차 재검토"
  * LVGI 상승 + 이자보상배율 하락 -> "채무약정(covenant) 준수여부 확인,
    계속기업가정 검토"
  * 재고자산회전율 하락 -> "재고 실사 표본 확대, 진부화 평가손실 검토"
- 난이도: 중간 - 매핑 테이블 설계(감사기준서/실무 지식 필요, 사용자의
  전문성이 가장 크게 기여할 수 있는 부분)만 하면 로직 자체는 단순 if-then
- 배치 위치: Day 4~5 사이, 이상탐지 결과가 나온 직후에 연동

[C. AI를 활용한 주요 공시 요약]

- 내용: DART에서 특정 기업의 최근 공시(수시공시, 주요사항보고서 등) 목록을
  가져와, 회계/감사 관점에서 중요한 유형(유상증자, 주요계약체결, 타법인
  주식취득, 전환사채발행, 감사인 지정 등)만 필터링 후 LLM(Claude API 등)으로
  3줄 요약 + "감사 시 확인 포인트" 코멘트 자동 생성
- 난이도: 높음 - 기존 3개 기능과 달리 별도 LLM API 연동(Anthropic/OpenAI 등
  API 키 발급, 프롬프트 설계, 호출 비용 고려)이 필요한 유일한 기능
  -> 2번 아이디어(AI 계약서 검토)와 마찬가지로 "LLM 연동" 리스크를 안고 감
- 대체 제안: 계약서 검토와 공시요약 둘 다 LLM 기능이므로, 시간 리스크를
  줄이려면 "LLM 연동 슬롯은 하나만" 두는 것을 추천 -> 계약서 검토보다
  공시요약이 구현 범위가 더 작고(문서 하나당 요약 1회 호출) 데이터도 DART에서
  바로 가져올 수 있어 더 실현 가능성 높음. 계약서 검토는 스트레치로 완전히
  후순위 처리 추천
- 배치 위치: Day 6~7 사이 스트레치 기능으로 배치 (핵심 MVP 완성 후 시간
  남으면 추가)
